# 06 · UI

One page (`src/app/page.tsx` → `src/ui/App.tsx`), client-rendered with React 19. The assistant sits on the left in a drawer; the right side shows the building as a 2D map, a 3D model or a table. Everything reacts to the same state, so all views always agree. This document is the blueprint for every browser file: what each component shows (exact copy), its props and state, the store actions it dispatches, and the API calls it makes. The stylesheets are reproduced verbatim in [Appendix E · Styles](appendix/E-styles.md). The 2D plan renderer, `floorLayout.ts` and the 3D scene internals are specified in 07 (verbatim in appendices F and G), and so is the 2D zoom maths `mapZoom.ts`. Every other browser file (`mapZoom.ts` included) (components, store, actions, API client, helpers) is copied verbatim in [Appendix I · Source files](appendix/I-source.md), so this document explains them and appendix I gives their exact markup.

Approved prototype (private to the project owner): https://claude.ai/artifact/Wt2Bzr8ybs9HvDks36PmTe. This spec describes what is built; it can be rebuilt from the docs without the prototype.

## Page shell
**`src/app/layout.tsx`** (server component): imports the eight stylesheets in cascade order (`base`, `shell`, `cards`, `map`, `sheets`, `table`, `admin`, `responsive`; Appendix E); loads fonts with `next/font/google`: `Barlow` (subsets `latin`, weights 400/500/600/700, `variable: '--font-barlow'`, `display: 'swap'`) and `Barlow_Condensed` (weights 500/600/700, `variable: '--font-barlow-condensed'`, `display: 'swap'`); `metadata` = title **"REPH Room Assistant"**, description "Book rooms at REPH Bldg. H and Iloilo with an AI assistant and a live floor map."; renders `<html lang="en" className={barlow.variable + ' ' + barlowCondensed.variable}><body>{children}</body></html>`.

**`src/app/page.tsx`**: `export default function HomePage() { return <App />; }`.

**`src/ui/App.tsx`** (`'use client'`):
- `App` creates one `QueryClient` (in `useState`) with `defaultOptions.queries = { retry: 1, refetchOnWindowFocus: false }`, then `QueryClientProvider` → `Gate`.
- `Gate` (sign-in first): registers `whenSignedOut(() => forgetUser(client, null))` (a 401 from any `api` call goes back to sign-in) and reads `useSession()`. While pending: an empty `<div class="app-loading" aria-busy="true">`. On error with no answer yet (a failed re-check keeps the last answer): `<main class="signin">` with a `.signin__card` (`role="alert"`) "Can't reach the app server. Check your connection and try again." and **Try again** (refetch). No user: `<SignIn />`. `user.mustChangePassword` (after an Admin reset or for a new account): `<SetPassword user={user} />` (S19) instead of the app. Signed in: `<StoreProvider key={user.login}>` → `Shell`, so the next person starts with an empty store (chat, results, drawer state).
- `Shell` renders, in order: `ClockSync`, `ConfirmLink`, `ChatDrawerMemory` (render nothing), `TopBar`, `<div class="main">` (plus `main--chat-hidden` when the drawer is hidden) holding `ChatPanel`, `MapPanel`, `ChatReopen`; then, when open, `RoomSheet` (`state.sheetRoomId`), `MyBookings` (`state.bookingsOpen`), `NewBooking` (`state.newBookingOpen`), `MessagesSheet` (`state.inbox`).
- `ClockSync`: when `useHealth()` returns, `offset = Date.parse(health.now) − Date.now()`; default slot = server now **rounded down** to the half hour, for 1 hour; dispatches `clock` (the slot is only used when none is set yet).
- `ConfirmLink` (once per page load): when the URL has `?confirm=<id>` (a confirm link from an AI app, 05 MCP), removes the parameter (`history.replaceState`), then `api.proposal(id)` → `showProposal(proposal)` for `kind: 'book'` or `showCancel(cancel)` for `kind: 'cancel'`; a failure dispatches the error `banner` with the server's message ("This confirm link has expired or was made for someone else. Ask the AI app to prepare it again.") or "That confirm link did not open." Signed out, the `Gate` shows sign-in first and keeps the URL, so the card opens right after signing in.
- `ChatDrawerMemory`: on mount reads `localStorage['reph-chat-hidden']`; `'1'` → `chat_hidden: true`. After that, every change writes `'1'`/`'0'`. Storage errors are ignored.
- `ChatReopen` (only while hidden): button `.chat-reopen` (chat-bubble icon + label **"Assistant"**, `aria-controls="assistant"`, `aria-expanded="false"`) → `chat_hidden: false`; an orange dot `.chat-reopen__dot` while `unread` or `streaming` (`aria-label` "replying" while streaming, else "new reply").

## Sign-in (`SignIn.tsx`, `session.ts`)
Everyone signs in first (demo accounts, 04 Session). The signed-in person is the **Name of Requestor**: the forms show it read-only, and there is no name picker.
- **`SignIn`** (S10): `<main class="signin">` (full height, centred on a charcoal gradient `#34343a` → `#18181a` crossed by a RELX-orange diagonal band, like the reedelsevier.com.ph banner; the same background for the consent and new-password screens) holding `<form class="signin__card form-grid" noValidate aria-labelledby="signin-title">` (400 px wide at most, white card, 14 px corners, shadow): the brand (`.brand` tile "R" and **"REPH Rooms"**, shown on phones too), `<h1 id="signin-title">` **"Sign in"** (Barlow Condensed 28 px), `.signin__lede` "Book rooms at Bldg. H with the room assistant and the live floor map.", **Username** (`autoComplete="username"`, `autoCapitalize="none"`, `spellCheck={false}`, `autoFocus`, placeholder "firstname.lastname"), **Password** (`type="password"`, `autoComplete="current-password"`), the error alert when there is one (the same `.form-error` markup as the forms: red "!" icon and the text; both inputs get `aria-invalid`), **Sign in** (`.btn--primary.signin__submit`, full width; "Signing in…" and disabled while working), and `.signin__note` "Your username is the first part of your e-mail address."
- Submit: empty username (after trimming) or password → "Enter your username and password." without calling the API. Otherwise `api.signIn(username.trim(), password)`: success → `forgetUser(client, user)`, so the `Gate` renders the app; failure → the server's message ("Wrong username or password.", "Too many requests. Wait a minute and try again.", "Sign-in isn't set up on this server yet.") or "Sign-in failed. Please try again.", and the password is cleared.
- **`session.ts`**: `useMe()` → the signed-in `Person` from `useSession()` (throws outside the signed-in app, where it is never used). `forgetUser(client, user)`: sets the `['session']` query data to `user` and removes every other query except `health` (bookings, availability, rooms and results belonged to the person who left). `useSignOut()` → `api.signOut()` (errors ignored: the screen changes either way), then `forgetUser(client, null)`.
- A 401 from any `api` call except `/api/session` calls the handler set with `whenSignedOut` (`Gate`: `forgetUser(client, null)`); the assistant's own fetch does the same on 401. Either way the sign-in screen comes back and the next person starts clean.

## Cards (`src/ui/cards/*`)

Short status words in these cards (`shortStatus`): "In Progress" → "Requested", "Checked-In" → "Checked in", others as they are.

### Room states (`roomStates.ts`, unit tested)
`roomStatuses({ rooms, busy, slot, results, pending })` → `Map<roomId, { state, rank?, result?, busy }>` where `busy` = the room's bookings overlapping the slot (half-open). For each room, first match wins:
1. Any overlapping booking with `mine`, or the room is in `pending` → **yours** (keeps its result).
2. The room is in the results → available **fits** (with rank), partial **partial**, unavailable **taken**.
3. Not self-bookable → **unsuitable**.
4. There are results and `scoreRoom(room, request)` is null (wrong kind or too small) → **unsuitable**.
5. No overlapping booking → **free**; the overlaps cover the slot end to end (back-to-back joined) → **taken**; else **partial**.

`pending` (`useMapData`) = rooms of proposal cards in status open, confirming or booked that overlap the slot. So a room is "yours" as soon as its proposal card shows, before the API marks the booking `mine`.

`STATE_WORDS`: fits "fits", yours "yours", partial "partly free", taken "taken", free "free", unsuitable "not suitable". `shortName("Tester, Alpha")` → "Tester, A." (a name without a comma is returned as is). `reservedBy(status)` → `{ short, full, count }` or null when nothing overlaps: bookings sorted by start, one entry per holder ("You" for yours, else the owner); `short` = the first holder ("You" or short name) + " +N" for more; `full` = "You" or "Owner (Division)" joined with "; ".

|---|---|---|---|
| Fits | `--green-fill` / 2.5 px `--green` | Green dot (top-left); rank badge 1–3 (green circle, top-right) | Green carpet `#62c283`, glowing green wall-top strip `#16a34a` (glow 1.3), label with a green rank circle and a green border |

### Map data (`useMapData.ts`)

## Actions (`src/ui/actions.ts`)
`useActions()` returns `{ send, confirmProposal, checkAgain, confirmCancel, showProposal, showCancel, mapSearch, refreshBookings }`. `refreshBookings()` invalidates the `availability` and `bookings` queries. `ASSISTANT_DOWN` = "The assistant isn't available right now. You can still browse and book from the map."

**`readSse(body)`**: reads the byte stream with a `TextDecoder`, splits on blank lines (`\n\n`); in each chunk `event:` sets the event name (default `message`) and `data:` lines are joined with `\n` and parsed as JSON; yields `{ event, data }`.

**`send(text)`**: trims; ignores empty text or while streaming. Dispatches `user_message` and `assistant_start`. `POST /api/assistant` with `content-type: application/json` (the session cookie goes along; same origin), body `{ message, history: state.history, confirmedTickets: state.confirmedTickets }`. A non-OK response or no body → `assistant_error` with the body's `message` (or `ASSISTANT_DOWN`) and `retry: message` (none for 429). Then for each SSE event: `text` → `text`; `done` → `assistant_done {history}`; `error` → `assistant_error` (message, retry); `ui` →
- `focus_time` → remember the slot, dispatch `focus`;
- `room_results` → `results` (with the remembered slot, `source: 'assistant'`) and a `results` card;
- `proposal` → a proposal card (status open) and `select` its room;
- `cancel_request` → a cancel card (status open);
- `room_schedule` → a `schedule` card (the event without `type`); with exactly one room, also `show_room` with its floor;
- `draft_message`, `handoff` → their cards.
A 401 answer (the session ended) → `forgetUser(queryClient, null)`: back to the sign-in screen.
A stream that ends without `done` or `error`, or a network error before `done` → `assistant_error` with `ASSISTANT_DOWN` and retry (an error after `done` is ignored: the reply is complete).

**`confirmProposal(card)`**: only from status `open` (single flight). `update_card → confirming`; `api.confirm(proposal.id)`; success → `booked` with `booking`, `confirmed` with the ticket, `select` the room, `refreshBookings`; failure → 409 `conflict` (also `refreshBookings`), 410 `expired`, else `error`, with the error message.

**`checkAgain(card)`**: re-proposes the same details (`roomId, agendaType, agenda, participants, priority, trainingType, specialInstructions, hardwareRequirements, recurrence, start, end`) with `api.proposeBooking`; success → the new proposal, status `open`, no error; failure → 409 `conflict`, else `error`.

**`confirmCancel(card)`**: only from `open`; `working`; `api.confirm(cancel.proposalId)`; success → `done`, `confirmed`, `refreshBookings`; failure → 410 `expired`, else `error`.

**`showProposal(proposal)`** (map, room sheet, New booking): `assistant_start`, text "Here is your booking to confirm. Nothing is booked until you press **Confirm booking**.", a proposal card (open), `assistant_done` with the current history (unchanged), `select` the room, `assistant_open: true`.

**`showCancel(cancel)`** (a confirm link for a cancellation): `assistant_start`, text "Here is the cancellation to confirm. Nothing is cancelled until you press **Cancel booking**.", a cancel card (open), `assistant_done` with the current history, `assistant_open: true`.

**`mapSearch({ agendaType, participants, slot })`**: `api.search` (Manila) → dispatch `results` with `source: 'map'` and the warnings; returns the results.

**`useBookingOps(ticketNo)`** (My bookings, Bookings table) → `{ working, message, confirmingCancel, checkIn, askCancel, confirmCancel, keep }`. Every operation sets `working`, clears `message`, and on failure sets `{kind: 'error', text: ApiError message or 'That did not go through. Please try again.'}`. `checkIn` → `api.checkIn`, then `{kind: 'ok', text: 'Checked in. Enjoy your meeting!'}` and `refreshBookings`. `askCancel` → `api.proposeCancel` and keeps the proposal id (`confirmingCancel` true). `confirmCancel` → `api.confirm(id)`, `confirmed`, clears the id, `refreshBookings`. `keep` clears the id.

## API client (`src/ui/api.ts`)

## Helpers
- **`format.ts`** (always Asia/Manila, en-US): `fmtDay` → "Mon, Sep 28"; `fmtTime` → "3:00 PM"; `fmtSpan(start, end)` → "3:00–4:00 PM" (same AM/PM), "11:30 AM–1:30 PM", or across midnight "Mon, Sep 28, 10:00 PM – Tue, Sep 29, 2:00 AM"; `fmtWhen` → "Mon, Sep 28 · 3:00–4:00 PM" (or the cross-midnight span alone); `fmtTool` → "2026-09-28 10:30 PM"; `fmtToolDate` → "2026-09-26"; `toManilaIso(date)` → "2026-09-28T15:00:00+08:00"; `STATUS_WORDS`: Approved "Approved", In Progress "Requested – waiting for Admin", Checked-In "Checked in", Cancelled "Cancelled", Completed "Completed", Held "Held", Blocked "Blocked by Admin"; `firstName("Tester, Alpha")` → "Alpha".
- **`csv.ts`**: `toCsv(header, rows)` joins cells with commas and rows with CRLF (trailing CRLF); a cell starting with `= + - @` gets a leading `'`; cells with `" , \n \r` are quoted with doubled quotes. `CSV_TYPE = 'text/csv;charset=utf-8'`, `CSV_BOM = '﻿'` (prepended so Excel reads UTF-8).
- **`download.ts`**: `saveFile(filename, parts, type)` creates a Blob URL, clicks a temporary `<a download>`, removes it and revokes the URL after 1 s.
- **`ics.ts`**: `icsFile({ticketNo, agenda, start, end, location}, now)` → CRLF lines: `BEGIN:VCALENDAR`, `VERSION:2.0`, `PRODID:-//REPH//Room Assistant//EN`, `METHOD:PUBLISH`, `BEGIN:VEVENT`, `UID:<ticket>@reph-room-assistant`, `DTSTAMP`/`DTSTART`/`DTEND` as UTC `YYYYMMDDTHHMMSSZ`, `SUMMARY:<agenda>`, `LOCATION:<location>`, `DESCRIPTION:Room booking <ticket>` (backslash, newline, comma and semicolon escaped), `END:VEVENT`, `END:VCALENDAR`. Saved with type `text/calendar;charset=utf-8`.

## Responsive
- **Tablet (≤ 1199 px)**: assistant 380 px; demo clock hidden.
- **Phone (≤ 767 px)**: map side full width; the assistant is a fixed bottom sheet (40 dvh; expanded `calc(100dvh - 72px)` by tapping its header; grip bar on top; the collapse chevron points down). Hidden → the sheet slides off and a full-width bottom bar **Assistant** brings it back. The site select and the brand name are hidden (the "R" tile stays), so the top bar fits on one line. Search bar and floor row are single rows that scroll sideways. The 2D map fits the width (no minimum width, no sideways scrolling): pinch or the zoom buttons zoom in, and one finger then pans the plan; 3D keeps its aspect (one finger moves, two fingers turn and zoom). Sheets and the New booking modal become bottom sheets (88 dvh); form rows stack. In the top bar the user menu shows only the avatar (the first name is hidden), and the schedule card puts each row's time on its own line above the name. The sign-in card keeps the brand name.
- New booking modal: two columns at 900 px and wider, one below.

## Accessibility (WCAG 2.2 AA)
- Keyboard: everything reachable; map rooms, result cards and 3D labels are buttons; the 2D map zooms with + − 0, turns with R and Shift+R and, when zoomed, moves with the arrow keys (the zoom and turn buttons are real buttons too); the 3D canvas takes focus, moves with the arrow keys, turns with R and Shift+R, spins 360° with S and goes back to the start view with 0; table rows open with Enter or Space; Esc closes sheets; skip link to the composer.
- Screen readers: live region for finished replies; cards have headings; room `aria-label`s include state, rank and holder; the table has a caption, `scope` and `aria-sort`; pagination announces the range and the page; the 3D canvas has a summary label; Table view is the full text alternative to the map; invalid fields have `aria-invalid` and the error alert `role="alert"`.
- Focus visible: 2 px `--blue` outline, 2 px offset.
- Contrast: text ≥ 4.5:1; state borders ≥ 3:1 against the plate.
- Automated axe check: planned in the E2E tests (P1-12).

## Copy
- Plain, friendly, short. Times "3:00–4:00 PM"; rooms "Batanes, 3F"; dates "Mon, Sep 28"; names "Last, First" (short "Tester, A."). The Bookings table and details use the tool's formats: "2026-09-28 10:30 PM", "2026-09-26".
- Buttons say what happens: **Confirm booking**, **Book 2:00–3:00 PM only**, **Ask Alpha to swap**, **Open in Teams**, **Check again**, **Show on map**, **Export CSV**, **Call IT**, **New chat**.
- **Less text**: no help paragraphs under fields (rules show as errors or hover tooltips), no notes that repeat what a card or field already shows, no counts that the pager already gives, and assistant replies of one or two sentences.
- Sign-in: "Sign in", "Your username is the first part of your e-mail address.", "Wrong username or password.", "Enter your username and password."; **Sign out** in the top bar.
- Empty state: "Tell me when, how many people, and what it's for. Or ask who has a room, or anything about booking."
- Errors say what to do next: "I can't reach the booking system right now. Try again in a minute."
- Status words: Approved → "Approved"; In Progress → "Requested – waiting for Admin"; Checked-In → "Checked in"; Cancelled → "Cancelled"; Completed → "Completed".
